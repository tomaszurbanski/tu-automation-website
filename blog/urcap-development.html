Tworzenie URCaps: od zera do wdrożenia na robocie UR

Tomasz UrbańskiKwiecień 202512 min czytania

URCap (Universal Robots Capability) to rozszerzenie oprogramowania robota Universal Robots, które dodaje nowe funkcje do tabletu Polyscope. Dzięki URCaps możesz zintegrować chwytaki, czujniki, kamery, sterowniki PLC — bezpośrednio z interfejsu robota, bez potrzeby pisania kodu przez operatora.

URCap to różnica między "robotem, którego obsługuje inżynier" a "robotem, którego obsługuje operator na hali". To inwestycja w ergonomię i bezpieczeństwo wdrożenia.

Architektura URCap

URCap składa się z dwóch warstw:

  • Warstwa UI (Polyscope): komponenty Java/OSGi wyświetlane w tablecie — okna konfiguracji, węzły programu, panele instalacji
  • Warstwa daemon: serwer (Python, Java lub inny) działający na robocie w tle — obsługuje komunikację z zewnętrznymi urządzeniami, logikę biznesową

Komunikacja między UI a daemonem odbywa się przez XML-RPC (domyślnie) lub REST API.

Środowisko deweloperskie

Wymagania:

  • Java JDK 8 (nie nowszy — Polyscope 5.x bazuje na Java 8)
  • Maven 3.x
  • URSim — symulator Polyscope (wirtualna maszyna VMware/VirtualBox)
  • SDK URCap — pobierz z plus.universal-robots.com
  • Eclipse IDE lub IntelliJ IDEA

Instalacja URSim na Windows przez VMware Player jest najprostszym podejściem. Zalecam snapshot VM przed każdą instalacją URCap — łatwy rollback przy błędach.

Struktura projektu

Typowy projekt URCap Maven:

  • src/main/java/ — komponenty OSGi (Activator, NodeContribution, InstallationNodeContribution, ProgramNodeService)
  • src/main/resources/ — pliki FXML (UI) lub HTML5 (nowe SDK)
  • com.tu.urcap.daemon/ — katalog daemona (Python lub Java)
  • pom.xml — zależności Maven + plugin URCap

Przykład: integracja z Modbus TCP

Prosty URCap sterujący chwytakiem przez Modbus TCP:

1. Daemon Python (xmlrpc_server.py):

  • Serwer XML-RPC na porcie 40405
  • Funkcje: open_gripper(force), close_gripper(force), get_status()
  • Wewnętrznie — połączenie Modbus TCP do sterownika chwytaka

2. Komponent Java (ProgramNodeContribution):

  • UI z suwakiem siły chwytu (0-100%)
  • Tryb: otwórz / zamknij / pozycja
  • Generuje URScript: socket_send_string("grip:50", "gripper_socket")

3. Instalacja na robocie:

  • Kompilacja: mvn install → plik .urcap
  • Przeniesienie na pendrive lub przez SSH
  • Instalacja w Polyscope: System → URCaps → ładowanie pliku
  • Restart robota — URCap gotowy

URScript vs URCap — kiedy co wybrać

  • URScript: szybkie prototypowanie, jeden robot, prosty skrypt, programista piszący kod
  • URCap: wielokrotne wdrożenie, obsługa przez operatorów bez znajomości programowania, integracja ze złożonymi urządzeniami zewnętrznymi
  • PolyScope XML: gdy chcesz podzielić się programem bez zależności od daemona

Najczęstsze błędy przy tworzeniu URCaps

  • Blokowanie wątku UI: Nigdy nie wykonuj długich operacji sieciowych w wątku Swing. Zawsze użyj SwingWorker lub wywołania asynchronicznego.
  • Brak obsługi błędów sieci: Daemon może być niedostępny. URCap musi gracefully degradować — robot nie może się zatrzymać przez timeout.
  • Zakodowane IP na stałe: Zawsze pozwól operatorowi skonfigurować adres IP urządzenia w sekcji Installation Node.
  • Ignorowanie wersji Polyscope: API zmienia się między wersjami 3.x, 5.x i 5.11+. Testuj na docelowej wersji firmware.

Potrzebujesz URCap dla swojego robota UR?

Tworzę dedykowane URCaps integrujące Twoje urządzenia — chwytaki, czujniki siły, wizję maszynową, systemy PLC. Dostawa z dokumentacją i szkoleniem operatorów.
